# Thread lettering checkpoint — Phase4

## Font and geometry foundation

New implementation in `src/core/lettering.ts`; not yet exposed as a product at this milestone. It supports Latin/Cyrillic via the existing pinned Noto Sans and Arabic via the newly bundled Noto Naskh Arabic Regular2.021. Font bytes are SHA-256 checked before shaping, not replaced with system fonts. See `public/fonts/SOURCE.md` and both accompanying OFL licenses. The [official Noto Arabic font index](https://notofonts.github.io/arabic/) links the unmodified regular TTF; the [upstream license](https://github.com/notofonts/arabic/blob/main/OFL.txt) permits redistribution with its notice. No font installation, competitor asset or photo upload.

The existing installed @pdf-lib/fontkit1.1.1 provides OpenType contextual substitution/positioning and visual glyph order. [Fontkit's primary API documentation](https://github.com/foliojs/fontkit) distinguishes layout from simple character-to-glyph lookup. Local tests verify actual Arabic glyph forms differ from nominal character glyphs, retain the original logical string and connect `بب` differently from `ب ب`. No reversed Unicode string or fabricated joining marks. Pure Arabic, Latin and Cyrillic lines are supported; mixed Arabic/Latin/Cyrillic in a single line is **explicitly refused** until paragraph bidi is implemented. Missing glyphs and unsupported controls are refused. Input is one NFC-normalized line, up to64 code points; output complexity is bounded.

Actual positioned font paths are fitted in physical board units, preserving aspect. Circle/heart use a conservative interior rectangle. Independently implemented adaptive quadratic/cubic flattening has .2mm tolerance; no copied font-engine/source algorithm code. Deterministic4×4 subpixel nonzero-winding scanline rasterization preserves counters/holes and yields the actual solver target. The future guide preview must still render only the computed ordered thread sequence.

Outline pin placement samples each glyph contour by physical arclength, apportions24–240 pins, retains at least3 per contour and checks **all** pin pairs against the requested minimum physical distance. It never quietly drops dots/counters or decreases spacing/pin count. Unsupported small/complex text requires fewer pins/larger board/another text. These are glyph outline loops (including counters and joining contours), not an unsupported claim of a combined silhouette boolean union. Future bridge strands between loops must be present in the actual route and preview.

Initial mechanics tests6/6: Latin/Cyrillic/Arabic deterministic shapes/raster/pins, actual OpenType Arabic joining/connectivity, nonzero counters, circle/heart placement and explicit text/font/glyph/bidi/spacing refusal. This verifies mechanics, not craft readability/physical fabrication. A boolean clipping library's primary MIT license was inspected as a possible future outline-union option; **no dependency/code was adopted** because the required glyph-loop mode does not need it.
