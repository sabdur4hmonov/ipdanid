## Implemented behavior

- Shared UZ/RU/EN `PersonBackground` keeps a bounded original image, defaults white-background preparation on, and supports an exact original toggle. Processing is independent of single-face portrait priority. Generation waits for preparation; failed/uncertain model output retains the last image and exposes correction/retry instead of silently making the entire picture white.
- Pinned self-hosted MediaPipe Tasks Vision0.10.32, CPU delegate, official six-class SelfieMulticlass256 model version1. All hair, skin, face, clothes and accessory categories are retained; no largest-person/component filter. Multiple separate people are supported without identifying them or asserting a face count. Inference input is bounded to512px on the long side; source is bounded to1536px. Edge alpha is feathered, core foreground color is preserved, and background becomes opaque white.
- Source-space keep/whiten brushes, eight-stroke undo and restore-automatic-mask work independently of crop/resolution. Each of four string-art candidate photos keeps its own original, prepared mask, group choice and crop. Stale decode/model responses and unmounted views cannot replace a newer photo; unwanted calls are discarded before inference. Photos/masks are not uploaded or added to persisted guides.
- Explicit “Two or more people” disables single-face priority, face fitting and head-outline fitting/whitening. Crop controls stay available; users must keep everyone inside the chosen board. Automatic foreground retention itself does not depend on this checkbox. Single-person priority may still be enabled explicitly.
- Source segmentation replaces the old oval background reduction for newly prepared photos by setting its strength to0. Legacy target-space tools/guides remain available; explicit legacy comparisons must disable new source preparation and restore their original background strength. Saved instructions, strict source bindings and previous sequences are not rewritten.
- Prepared PNG download/share lets a user retain exact processed pixels after manual correction. To resume generation, reupload that PNG with automatic whitening off and identical crop/material/portrait settings. There is no promise that independently rerunning inference on a different photo/model reproduces an old target. Exact target/sequence hashes remain authoritative.
- Runtime/model are packaged with Android and atomically precached for browser offline use, including SIMD and fallback WASM. Model bytes are checked against SHA256 before graph creation. A reproduced Chromium HTTP-cache write race on the large model is fixed by a no-store byte fetch; the PWA cache still serves the immutable asset offline. No CDN, photographic API or photo POST.
