# Immutable owner API runtime snapshot

Written before implementation,2026-10-28. Final protected122asset build passed desktop3/mobile3/native1. No final owner preview or APK has been published.

Concrete release blocker found in the new preview launcher: its API manager would execute the workspace server. `GenerationQueue` creates a fresh worker from generation-thread.mjs for every fit; tsImport then reads generation-work.ts and core modules. Later repository edits could therefore change a supposedly frozen preview's future fits even though its web assets stayed immutable. Copying only the web build is insufficient. Previously frozen local-engine sites are untouched.

Before owner handoff, copy only an explicit source allowlist (`server`, `src`, `public`, package/lock/TypeScript configuration) and the installed `node_modules` into a NEW private runtime directory. Exclude top-level mutable tool caches and command shims, refuse symlinks/overwrite, hash-check every copied regular file. Never enumerate/copy repository output, tmp/data, .env, .git or owner photos. This is a filesystem snapshot of already installed dependencies, not an install/download/update. Worker bootstrap and dependencies must resolve from the copied runtime; use that runtime as the API working directory. Start the static preview separately against the immutable web copy. Keep explicit PIDs and stop only those owned processes on a failed prepublication check.

Meaningful regression test: snapshot a tiny real ESM API/worker/package fixture, mutate both original worker source and original package after the snapshot, then start a fresh worker from the snapshot and require the original output. Also validate no source-root private file or excluded mutable cache enters the snapshot. Actual owner prepublication acceptance must exercise gallery→static result→signed unlock/first-step through this copied API and show the real1000000ready inventory in mobile Admin, before publishing credentials. Use a fourth dedicated verification code; the three delivered test codes remain3credits. Export decryption key stays with the offline master. Preview sandbox data is never recommended for real production sales.

Check freeRAM>=1.5GiB before the snapshot/heavy browser work; copy one runtime once, no parallel heavy job. Only after final tests publish/freeze4217/API4657 and the new runtime directory. Full compatibility matrix remains independently bound to the accepted explicit local build and workspace API source; snapshot files must be byte-exact, not a different engine implementation.
