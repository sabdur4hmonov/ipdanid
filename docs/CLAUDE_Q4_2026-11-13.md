## What changed

- `src/core/classic-least-squares.ts`
  - New `CLASSIC_LS4_TUNING` (`classic-reference/4`, darknessGamma 1.2, importanceAmplitude 3), `classicLsDefaults(tuning)` and `ClassicTuning`.
  - `leastSquaresImportance(n, faces, amplitude = 1)`. Amplitude 1 is bit-identical to the old `1 + gaussian`.
  - `generateClassicLeastSquares` accepts `classicTuning`. If it is absent, the tuning of a supplied seed is used; otherwise /3. The **library default stays /3**, so every stored guide, seed and golden test is unchanged.
  - Settings keep the same key order and are recorded in `params.classic`.
- `src/core/validation.ts`: the classic3 contract accepts exactly the /3 or /4 settings object (selected by `params.classic.version`). Any other combination is rejected.
- `src/core/engine.ts`: `GenerateOptions.classicTuning?`.
- `server/generation-recipe.ts`: `serverClassicTuning(env)`. The default `"4"` gives /4, `CLASSIC_TUNING=3` rolls back, and any other value fails at startup. Tuning goes into the options. The recipe hash includes `classicTuning` only for /4, so /3 hashes stay byte-identical. `server/index.ts` reads the tuning once at startup.
- `src/core/generator.worker.ts`: new local classic3 works use /4; a resumed seed keeps its own tuning.
- `server/production-auth.ts`: admin login lockout. 5 failures per client within 15 min, or 200 overall within 1 h, lock that scope for 15 min. State is persistent in `owner_login_failures` (client stored only as a keyed digest; rows pruned after the window). Success clears the client counter. Audit rows: `admin.login.failed/locked/blocked/success`. A locked attempt is refused before the scrypt check. `server/index.ts` passes the client IP. `server/privacy-retention.ts` classifies the new table as staff/shared.
- Audit S3 (random pepper fallback) needed no code: `server/local-config.ts` already persists a stable local pepper, and production requires `CODE_PEPPER`.
