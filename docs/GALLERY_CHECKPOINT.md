# Phase15 C11 — consented finished-craft gallery and reviews

Menu → Account & shop → Customer gallery is a real client/server feature. Visitors can see approved posts; a registered or kit-account maker can explicitly select a finished-item JPEG/PNG, choose a public alias/title and optionally provide feedback/rating. The form separately requires finished-work, sharing-rights/people-consent and public-publication attestations, all unchecked initially. No source from the portrait editor is automatically selected or uploaded. This is explicit customer attestation plus human moderation, not an image classifier, identity check or verified-purchase claim. Public copies may be retained by their viewers; consent text states this before upload.

The client reuses bounded local JPEG/PNG inspection/decoding (15MB/24MP), correct orientation, white alpha compositing and a maximum768px PNG. A server-owned strict RGB/RGBA8 noninterlaced PNG decoder validates headers, chunk lengths/CRC/order,96–1024px dimensions,≤2.5MB compressed input and exact bounded zlib output before reconstruction. It implements the five byte filters described by the primary [W3C PNG filtering specification](https://www.w3.org/TR/png/#9Filters). It rejects animation, indexed/unsupported transparency and malformed/oversized streams. Normal RGB re-encoding and actual area-averaged240px thumbnail discard all ancillary camera/text/profile metadata and hidden alpha colors. Browser file inputs still accept normal JPEG/PNG because the app first normalizes them to this restricted upload subset. It does not remove visible personal information from pixels; that remains an explicit human review responsibility.

SQLite stores only normalized full/thumbnail images, public fields, owner/request identity, versioned consent and timestamps. No original filename, camera metadata, email or session credential enters gallery records or public responses. New posts are pending/private. Support-permission staff/manager/owner can view private full images and approve/reject with a categorical reason; code/finance/catalog permissions alone cannot. Dedicated method+route allowlists and actual server authentication enforce this. Revision checks refuse stale moderation/deletion. The public allowlist excludes owner/request/fingerprint/reason/revision; only approved unexpired entries and their current ratings count. Lists are cursor-paged at12, using thumbnails; full image reads separately enforce public approval, owner scope or moderator scope. Lists do not load full-image blobs into their result sets.

An immutable request key/fingerprint plus transaction-bound quota/idempotency checks prevents duplicate/lost-response publication or changing an accepted upload under the same key. Ten live/recent submissions per account; withdrawal does not reset today's quota. Wrong-owner image/delete requests are404. Withdrawal scrubs live image/thumbnail/title/alias/review/rating/fingerprint immediately and cannot be undone by an old submit retry. Pending posts expire30days after submission. Rejected retention is at most30days and cannot extend an unpublished post's original deadline. Approved posts expire365days after first approval; reapproval cannot extend that deadline. Queries and the existing one-minute maintenance task prune expired media. Minimal scrubbed tombstones remain30days for replay protection, then are removed. Account-wide erase service is implemented/tested for C21 integration. SQLite WAL/backups and third-party saved public copies are not falsely claimed to be remotely erased instantly; unified account/backup policy remains C21/C24.

API responses are no-store and the offline shell excludes all /api/ paths. Actual CacheStorage checks found no gallery/API media. Draft images/private lists are volatile and cleared on session change/unmount; large images also close when hidden. No photo payload is written to localStorage/Preferences, an analytics event or an audit line. Audit entries contain operation/actor/entity/time only. Device/production use and real customer content were not exercised; all acceptance media are our original code-drawn synthetic test fixture on fresh local DBs. Owner setup/use: GALLERY_UZ.md.
