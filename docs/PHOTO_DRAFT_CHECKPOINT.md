# Editable photo retention — C21c

The ordinary free-photo editor now offers **Menu → Continue editing later**. Saving is explicit. One normalized working photo, the exact Float32 cutout mask, face regions, free placement/rotation, caption, line count and original kit configuration are retained on this device. A new save replaces the one older draft. It never uploads anything or grants build access. Immutable generated guides and receipts are separate.

`editable-photo/1` is a bounded binary envelope: UTF-8 metadata, unmodified RGBA working pixels, little-endian float mask and a SHA-256 checksum over all preceding bytes. The normalized source is at most1536×1536 and has no camera EXIF; this is not a promise to retain the full camera original. Maximum envelope14MiB, metadata32KiB, mask1024×1024, strict field allowlists, bounded transforms and original kit validation. No tokens/credentials/publication permission are accepted. Version1 restores preparation9 free placement without rerunning segmentation.

IndexedDB keeps a single slot through a serialized queue. Success is shown only after transaction commit. A failed replacement preserves the previous committed value. Delete is ordered after earlier saves. Drafts become unreadable after30days; expired/corrupt bytes are removed on the next read. A closed browser cannot run background disk erasure; clearing site/app storage also removes the draft. This is local storage, not encryption against someone with access to an unlocked device. Local drafts are explicitly device-owned, not automatically uploaded or reassigned on account login.

Kit templates are memoized per config in CustomerStudio; changing shape no longer rebuilds all three drill patterns. Identical config fetches/restores preserve the memo. A delayed current-kit response cannot overwrite a restored kit revision. No pin coordinates, algorithms, old guide hashes or physical rendering changed.

The first restore browser tests exposed synchronous full-resolution tone preparation blocking React render. Kit memoization alone did not resolve this. Reference grayscale/CLAHE/stretch/unsharp arithmetic now runs in a dedicated bounded worker; changing a photo or mask terminates the superseded worker and fences late responses. Colour placement stays interactive while the exact target prepares. Generation waits for the matching target. A browser test compares every worker output byte to the retained reference implementation. The original manually edited-mask flag survives restoration as well as its exact bytes.

Private account backup, account-wide erasure and retained financial-record rules are subsequent C21c work. This checkpoint does not close C21 or claim website-to-app original-photo migration yet. Validation results and initial failures are recorded in AGENT/LOG.md after execution.
