An owner-only access permission grants an existing registered/kit account a partner membership and revisioned product/volume terms. Other staff cannot grant memberships. Partner requests always derive scope from their authenticated account, with exact field allowlists and UUID validation; client-supplied partner IDs/prices/profiles are not trusted. Portals expose only that partner's terms/campaigns and aggregate claim counts, never recipient account IDs, sessions or plaintext codes. Owner lists are bounded to200 partners and100 campaigns per partner.

Quotes use actual active product prices, credits, stock and known immutable standard/registered profiles. One to six monotone volume tiers have positive exact minor-unit prices, safe total arithmetic, bounded min/max batch(≤100), code/credit expiry and lifetime allocated kits(≤10000). Quotes bind terms/product revision, exact profile/credits and expiry contracts for15minutes. Quote retries bind request key/count;20live/100daily quote and10pending campaign limits bound unapproved work. Request retries cannot create a second campaign or change its quote/name. Owner product/terms/stock changes require a fresh quote before approval. An owner can always disable a program after its SKU is retired; a failing regression exposed and fixed an over-strict availability check on this administrative operation.

Drafts reserve no stock or credits. Explicit owner authorization approves code issuance and atomically subtracts real catalog stock within the partner's lifetime allocation. This is authorization of an owner-funded/manual B2B campaign, not a claim of provider payment, invoicing or physical shipment. No money or message is sent. Approved unused reservations last seven days, then bounded maintenance returns stock once. Unissued cancellation also returns stock once. After codes have been distributed, revocation never invents returned physical boards or resets the allocation. Existing redeemed credits/old guides remain available; revoked code credentials cannot log in again.

Only the authorized partner can issue an approved batch. The existing KitStore contract creates real random32-character kit codes with the quote's exact profile, per-kit credits, code expiry and credit lifetime, without changing global kit defaults. A scoped internal terms override and nested savepoints compose issuance with campaign finalization inside one outer transaction. An injected finalization failure proves all new batch/code/audit inserts roll back; retry creates exactly one batch. Plaintext is returned only once and is never stored in partner/campaign/audit tables. A lost issued response requires explicit inspection/revocation/reissue, never automatic duplicate issuance. Existing kit redemption binds one account; an attached different account is refused. Codes remain bearer credentials and must be kept private; possession is not verified recipient identity.
