# Phase15 C06 — actual continuous QR ribbon plan

Separate experimental product, reachable through Expert → Menu → Grid crafts. It is explicitly incompatible with the standard240 nail kit. H error-corrected QR payloads are bounded to80UTF-8 bytes and version≤5; control/format characters and empty input are refused. Quiet zone is4modules. Uses existing pinned MIT qrcode1.5.4; the new test-only jsQR1.4.0 decoder is **Apache-2.0**, not MIT, and is not bundled in the customer app.

The original plan merges contiguous dark module runs and lays four1.4mm-wide **flat ribbon** strokes per5.6mm module. Each front stroke is followed by an explicit backside transfer through a separate white1mm perforated sheet. Hole centres are distinct, diameter.6mm/minimum spacing1.4mm; a soft ribbon must fold through the hole. There is one uncut path, no hidden front transfers or photo/matrix overlay. Physical ribbon thickness/folding/board tear resistance and actual scans remain OWNER/O06, not software acceptance. Thread length includes both sides, sheet passages and.5m end allowance. No classic engine or old guide changes.

New `iprasm.qr-stitch/1` hashes payload, EC, physical material, exact holes, ordered side-specific moves and material accounting. Canonical rebuild rejects edited moves/coordinates/material. Canvas/SVG/PDF/CSV/JSON use that same plan. Real canvas displays the front strokes only; back view is explicit. The exact hole SVG and PDF provide full-size and A4 templates/50mm calibration, plus every move's side/from/to/mm coordinates. Tiny hole labels are not overprinted on the physical template. PDF preview is generated from the actual front moves.

Local/native Preferences library is bounded, validated, serialized with revision/sequence checks and browser locks; separate tabs cannot overwrite confirmations or stale-delete. Progress saves before UI advances and resumes offline. Imports validate/fork identity; generated payloads never navigate or upload automatically. No new live service or paid QR entitlement is advertised.

Initial round-cord candidates1.2/1.4/1.6mm did not robustly decode at full raster size (one280px view happened to decode). They were rejected rather than promoted. The final explicitly different flat-ribbon geometry decoded from an independent analytic stroke raster for text/link/Cyrillic; actual browser canvas acceptance is recorded after execution in PROGRESS/LOG. Do not treat rejected `output/phase15/qr/thread.png`/ideal-control probe images as final output.

Primary sources: [DENSO quiet-zone requirement](https://www.qrcode.com/en/howto/code.html), [qrcode encoder API and MIT license](https://github.com/soldair/node-qrcode), [jsQR decoder](https://github.com/cozmo/jsQR). No competitor assets. Setup: [QR_CRAFT_UZ.md](QR_CRAFT_UZ.md).
